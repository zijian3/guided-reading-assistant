# Guided Reading Assistant · 读书导读助手

把 Markdown 书稿、译稿或学习资料变成一本持续共读的书。在 Obsidian 中使用本机 Codex，支持全书路线、分次阅读、复述纠偏和自由追问。每本书有独立提示词、会话、阅读位置与理解记录。

## 开始使用

1. 在 Obsidian 的「设置 → 社区插件」中启用「Guided Reading Assistant」。通过命令面板搜索「读书导读助手」并打开书架，或点左侧书本图标。
2. 点击「添加书籍」，填写书名和正文路径。支持 Vault 内的 `.md` 文件或章节目录；多个路径每行一个，按填写顺序阅读，目录内部按文件名自然排序。建议用 `01-`、`02-` 编排章节。
3. 选择通用、哲学、方法实践或文学模板，然后修改为这本书的导读提示词。可以写学习目的、你的基础、希望追踪的问题、讨论风格与证据边界。
4. 点击「建立阅读路线」，再点击「开始／继续导读」。打开正文阅读，回到输入框用自己的话复述，或直接追问。`Ctrl+Enter` 发送。
5. 点击「保存阅读记录」，写下自己的理解、疑问和自评；记录会成为普通 Markdown 笔记。然后主动切换下一阅读单元。

选区分析在正文编辑器的右键菜单和命令面板中。选区需属于所选书籍的同一阅读单元；插件会定位到该单元再发起分析。

连接时先点击导读面板顶部的「刷新 AI 连接」，它会重新建立连接并读取账号实际可用模型。模型与思考强度在插件设置中选择；留空采用 Codex 默认。插件自动寻找本机 Codex，也可指定完整可执行文件路径。沿用本机已有登录，不要求另填 API Key。若本机确实未登录，请在终端运行 `codex login` 后重新检测。

## 书籍配置

默认配置目录：`读书助手/书架`。每本书是一份可直接编辑的 Markdown：

```yaml
---
type: guided-reading-book
id: a-stable-book-id
title: 某本书
source:
  - 书库/某本书
notes: 读书助手/阅读记录/某本书
reading_order: source
external_sources: off
spoiler_policy: unrestricted
---
```

YAML 之后的正文即本书导读提示词。`external_sources: on-demand` 允许你明确提出外部资料需求时检索；默认关闭。`spoiler_policy: strict` 限制发送给 AI 的材料范围，并禁用外部检索。

提示词和来源变化后，下次提问会开启新的模型会话。本地对话和你保存的阅读笔记仍可查看。「新会话」可用于旧会话无法恢复时重新开始。

## 记忆与证据

- 位置代表打开的阅读单元，不等于读完或理解。模型回答不会自动推进位置。
- 理解记录由读者主动保存。AI 的讲解、总结或评价不自动成为读者的掌握证明。
- 单次导读发送当前单元、前一单元、近期对话与读者保存的记录；问题可以匹配较早正文。切换单元时开启新模型会话，用这些材料继续主线。
- 全书路线以目录、跨章节正文摘录及已读记录为依据。路线是可修订的初稿；没有提供完整正文的地方应明确标为未核对。超大书稿不会一次完整塞入模型。
- 严格防剧透只发送已开放范围并隐藏未来目录标题；大模型可能已有书籍记忆，因此仍无法保证绝对无剧透。
- 对学习资料、译稿和原文应在本书提示词中明确区分。不要把助手备课记录直接当成原著或读者已经形成的观点。

位置、草稿、对话、路线和阅读记录索引保存在 `.obsidian/plugins/guided-reading-assistant/sessions/<书籍id>.json`，保留上次快照 `.bak`。普通理解笔记保存在本书的 `notes` 目录。插件目录可能被 Vault 的 Git 规则忽略，跨设备同步时需另行包含配置和会话；Codex 的模型会话依赖本机历史，无法恢复时可点「新会话」。

插件只在你发起导读时调用模型。对应提示词、正文片段、对话和阅读记录会交给当前 Codex 服务处理。Shell、文件写入、连接器和额外 agent 均关闭；所有本地文件选择与笔记写入由插件处理。

## 开发与安装

要求桌面版 Obsidian 1.8+、本机可用的 Codex CLI、Node.js 20+。

```sh
npm ci
npm test
npm run build
npm run install:plugin -- "Vault 的绝对路径"
```

安装脚本只复制构建产物，随后在 Obsidian 社区插件中启用。更新已经启用的版本需重新加载插件。源码中的 `scripts/smoke.cjs` 可检查本机连接，添加 `--turn` 会发送一条不含书稿的验证请求。

首版支持 Markdown。PDF、EPUB、OCR、多本书之间自动比较与自动备课尚未实现。

插件独立实现 Codex App Server 协议连接，不包含其他 Obsidian 插件代码，也不要求安装拉康插件。使用 MIT 协议，见 `LICENSE` 和 `NOTICE.md`。

## 隐私、账号和外部文件

需要单独安装并登录官方 Codex CLI。具体模型权限、额度与费用由你在 Codex 中使用的账号和服务决定；本插件不收费，也不收集遥测。

只有你主动发起导读时，相关书稿片段、路径与行号、本书提示词、近期讨论和理解记录才会发送给 Codex 当前配置的模型服务。允许外部检索时，搜索请求也会交给其搜索服务处理。请参阅 [OpenAI 隐私说明](https://openai.com/policies/privacy-policy/)；通过其他模型服务使用 Codex 时，以对应服务的条款为准。

插件会在系统 PATH、常见安装目录与 Codex 桌面应用目录中查找 Codex 可执行文件，并在后台运行它。这涉及库外的可执行文件与 Codex 自己的登录、配置、会话存储；插件不会读取或复制登录凭据。只读会话限制模型工具，本机 Codex 进程仍会维护它自己的配置和历史文件。

界面首版使用中文；社区目录名称采用英文 Guided Reading Assistant。
